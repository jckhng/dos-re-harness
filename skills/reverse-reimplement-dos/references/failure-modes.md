## 1. Harness Errors

### Scripted input lands on the wrong screen

Cause: startup timing varies and a wall-clock key press reaches another title,
credits, or attract page.

Action: gate input on a screen signature or explicit state predicate. Store the
sequence in a versioned movie.

### A late scene cannot be reached reliably

Cause: natural scheduling depends on RNG, hidden counters, actor population, or
earlier input.

Action: capture those fields first. Use a documented warp only to study the
presenter, then separately prove that natural gameplay reaches the same entry
state.

### Original captures vary unexpectedly

Cause: mutable configuration/save data, unpinned emulator build, stale clean
mount, or mixed specimen version.

Action: hash inputs, restore tracked baseline files into a private clean mount,
pin the backend, and record the full command in an evidence manifest.

## 2. State and Scheduling

### A one-frame teleport appears

Likely causes:

- spawn position rendered before initialization;
- fixed-point/integer conversion applied in only one path;
- old and new coordinate origins mixed;
- update and draw order reversed;
- stale object slot rendered for one frame.

Capture the object slot before and after spawn, including raw fixed-point
values, state flags, sprite ID, and update phase.

### Late actors or events occur at different ticks

Do not tune delay constants first. Compare RNG state, RNG callers, object-slot
allocation, entity iteration order, hidden countdowns, and branch flags.

### Particle effects look plausible but wrong

Recover the original RNG algorithm, seed source, call count, velocity tables,
integer widths, and per-frame update order. A replacement particle system
cannot converge to pixel parity.

## 3. Coordinates and Sprites

### Sprite remains consistently offset

Check whether coordinates represent left edge, center, baseline, hotspot, or a
fixed-point origin. Compare the raw object field with the draw-call arguments.
Avoid permanent correction constants unless documented as an adapter around a
known convention mismatch.

### Walking animation slides

Check sprite-frame cadence separately from movement cadence. Confirm whether
the frame advances before or after position update and whether the final step
uses a distinct frame or visibility transition.

### Actor is drawn through a building or doorway

This is usually a layer-state problem, not a sprite problem. Recover the exact
threshold where the actor changes from foreground to occluded, and the tick
where its object is removed.

## 4. Presenter and Page Behavior

### Door sound plays but door opens one actor late

Separate sound trigger, door-state mutation, and draw timing. Confirm whether
the first entering actor changes the state before or after the frame is
presented.

### Old banner overlays the next scene

Recover the original page clear, page swap, dirty rectangle, and skip branch.
Do not add a broad full-screen clear unless the original performs one.

### Explosion is slow or missing frames

Check whether the implementation updates on coarse scene states while the
original runs a per-tick presenter. Capture every displayed frame and state
change, not one screenshot per second.

### Skip jumps to the wrong result

The interrupt path may call cleanup and terminal presenters directly rather
than merely setting the scene timer to its maximum. Recover its control flow
and final page selection.

### Final screenshot matches but transition looks wrong

Use sequence alignment. Compare frame count, transition anchors, palette
changes, draw order, and repeated/held frames.

## 5. Assets

### Procedural art looks close but never matches

Inventory the original resources and call sites. If a source resource exists,
recover and use it. Reserve procedural output for debug or explicit remaster
mode.

### A resource appears empty

Do not classify it from visual dimensions alone. Inspect codec tags, callers,
neighboring records, runtime destination, and special zero-dimension paths.

### Destroyed or terminal art cannot be found

It may be assembled from shared sprites, generated by a compiled blitter,
drawn into a retained page, or selected through a resource remap. Capture
resource loads and draw calls across the full presenter.

## 6. Audio

### Every candidate is silent

Check device mode, resource remap, decoder framing, sample rate, signedness,
channel assumptions, and whether the resource contains commands rather than
PCM.

### A candidate sounds like an unrelated effect

The extraction may be correct while the call-site ID or device remap is wrong.
Trace the actual runtime resource request under the active audio mode.

### Persistent sound plays only once

Tie start/stop behavior to actor or scene lifetime. Capture audio events until
the actor is destroyed or leaves the screen.

### Human identification is needed

Export isolated candidates with resource ID, variant, decoder settings, and
hash in the filename or manifest. Record labels as evidence. Do not repeatedly
replace IDs without preserving results.

## 7. Decompiler Errors

### Decompiled control flow contradicts runtime

Inspect instructions, calling convention, segment assumptions, overlays,
indirect calls, and integer types. Runtime behavior wins.

### A semantic function name later proves wrong

Do not silently reuse the name. Record the superseded hypothesis and new
evidence. Incorrect confident names propagate bad architecture.

### A pointer or field has impossible values

Check segment base, near/far pointer form, signedness, aliasing, union layout,
and whether the dump came from DS or SS.

## 8. Workflow Errors

### Repeated visual iteration makes no progress

Stop editing. Improve capture timing, expose missing state, recover the call
path, or add a sequence comparator.

### One fix breaks another ending

Look for a shared original presenter or resource path. Replace duplicated
scene-specific implementations with the shared behavior.

### Harness becomes target-specific

Move addresses, executable names, mutable-file overlays, schemas, and scene
movies into a target adapter. Keep backend capabilities and comparisons
generic.

### Reimplementation becomes host-specific

Move process launch and OS integration behind adapters. Keep simulation,
decoders, rendering rules, and asset loading portable and independently
buildable.
